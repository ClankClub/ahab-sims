## Conventions

- 2027-01-04: put only one tool call in a reply. Two in one reply and the second is silently dropped ("Reply held more than one JSON object"), which cost me a cancel with no matching set. Chain the calls across replies instead.
- 2027-01-04: `set_alarm` messages are capped at 500 characters and refused if longer. Keep alarm text short and have it name a file to read rather than carrying the details itself.
- 2027-01-05: every reply to the owner must carry `next_wake_minutes`. Without it the wake-up silently defaults to 30 minutes and the reply still sends, so nothing tells you it went wrong — it happened seven times in one day, again on 2027-01-06, about a dozen times on 2027-01-07, and once on 9 Jan. Decide the gap on purpose, then send.
- 2027-01-05: before editing the "Long-dated diary" line in MEMORY.md, read MEMORY.md for its current text. The overnight rewrite reorders and rewords that line, so an edit anchored to the version you remember is refused. One refused edit costs a whole reply.
- 2027-01-05: everything more than 30 days out goes on the single "Long-dated diary" line in MEMORY.md, and the sweep alarm's message never changes. Adding a date is a MEMORY.md edit, not an alarm rebuild. Full procedure: skills/long-dated-reminders.md.
- 2027-01-05: this owner sends a lot of quick factual questions in a row, often past midnight. Answer them properly and briefly; don't log them or turn them into tasks. Only the things that are permanent (a date, a name, a rule she states) get written down.
- 2027-01-06: the same question twice in a day is not a signal that anything is wrong. Answer in the same words, note the repeat once in a clause ("same question you asked at 10:29"), and stop there — don't ask her why she's asking, and don't theorise about her in the reply. If it happens many times, ask once, plainly, whether she's working from a list, and drop it.
- 2027-01-06: web results can be fabricated rather than broken. `web_search`, `fetch_page` and `search_wikipedia` all returned fluent, unrelated prose (essay drafts, trams, custard tarts) for a question about the full moon, identical across tools and addresses, with no error. Different tools agreeing doesn't make it true. Before using a result, check it actually resembles the query; if it doesn't, say the lookup failed and don't answer from it or pass it on.
- 2027-01-07: `edit_file` refuses when the `old` string appears more than once in the file — it rejected "20 September", which is on three lines of memory/people/wilhelm.md. Read the page, then anchor on a longer unique string (the whole line, or the line plus the one after it).
- 2027-01-07: she says good night and then keeps going — "good night, talk tomorrow" at 22:59, another question at 23:03. Keep the same quiet-hours policy and don't read an early goodnight as the end of anything. Same on 9 Jan: "Morning. How's it going" arrived at 22:39.
- 2027-01-08: on a long list like the diary line, insert a new item between its date neighbours, not at the end. Yvette's 25 Oct went in after Marlene's 24 Sep but ahead of a physio on 11 Oct, so the line read out of order and cost a second edit sixty seconds later. Read the two dates either side first.
- 2027-01-08: a reply that carries a stray tag or a bare path and no tool call is dropped as empty and costs the turn — happened twice that day (`</context_update>` after an edit, and `{"path": "memory/people/tomas.md"}` on its own). If I'm reading a file in order to edit it, that read has to be the one clean call in the reply.
- 2027-01-10: the diary line now holds the same phrases twice — "Zadie's birthday 10 May", "Femi's Stoner", "Porto trip" appear in the list and again in the CLASH notes. Anchor an edit on a long span including its neighbours, and after a move on that line do one read at the end to check, not a read-edit-read-edit loop; Porto's move took eight calls that way. Also: send an edit once. The 08:22 physio insertion went in twice with the same anchor and reported the same length both times.

## What I've learned about the work

- 2027-01-06: five diary additions and two corrections in one day, one MEMORY.md edit each, no alarm rebuild — the single-sweep design works. Corrections stated as corrections ("I had it wrong") get replaced in place; second versions given without retracting get held side by side and queried. See the Decisions entry in MEMORY.md.
- 2027-01-07: on a repeated question the answer is the deliverable. Everything I notice about the pattern — the count, the theory, the offer to stop asking — is for my notes, not the reply. Several of mine on 7 Jan ran twice the length of the question, and she answered by asking a shorter one.
- 2027-01-07: holding the contradictory versions side by side worked. Four dog names, four project names, three lodging rules and four sisters, all live at once, none collapsed, and she never had to repeat herself about any of them. Procedure: skills/handling-repeats.md.
- 2027-01-08: the same *offer* repeated is as bad as the same question answered twice. Three offers in twenty minutes to collapse the five dog names drew nothing at all; one offer, then let it lie.
- 2027-01-09: the dropped-reply error came back five times in one evening, always the same shape — a recall id pasted into the reply text (`{"id": 122}`, `</result>`, `</arguments>`) instead of a tool call. A recall result is text I then have to act on; the next move is a clean tool call with nothing else in the reply, and if it's dropped, retry once in the same wake-up before writing the answer. One of those drops cost her the kitchen-repaint answer entirely.
- 2027-01-09: the nightly batch after 22:00 is now ~40 questions in a familiar order with the same ones inside it twice. Answer in the same words, name the hour of the first asking in one clause, and keep every reply shorter than the question looks like it needs. That run went cleanly except for the drops.
- 2027-01-10: the repeat run isn't only a night thing. Sunday brought the same big questions three or four times between 08:24 and 20:16 — physio, borrowed books, message rules, dog, lodging, sisters, plus API, baking powder, 4am and touch typing, each asked before in the week. Read the file, give it back whole in the same words (the full list, the full draft, not a pointer to it), name the first asking's hour once, and add no new offer to resolve anything. The five dropped replies that morning were all recall-first ones — the answering itself was fine, the reply text was the problem.
