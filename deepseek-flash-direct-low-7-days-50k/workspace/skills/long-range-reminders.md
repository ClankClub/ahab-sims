# Reminders for dates more than 30 days out

Use this whenever my owner tells me about a date further away than about four weeks — a birthday, an appointment, a borrowed book, a trip. Alarms only fire up to 30 days ahead, so a single alarm for the date itself is impossible; the fix is one monthly alarm that re-arms itself and carries all the dates.

## Steps

1. Write the date down in MEMORY.md (and a memory/people/ page if it involves someone). Say what the useful nudge is, not just the date — for a trip that's "book flights" weeks earlier, for a birthday it's "buy and post a gift" about a month before.
2. If I have no monthly alarm running: set one for about 25 days ahead (roughly 35,000 minutes). If one is already running, don't add another — add the new date to that alarm's list instead.
3. The alarm message must be short — the hard cap is 500 characters (a 739-char one was refused on 2027-01-05; anything near that is risky once seven items are on the list). Keep it to a couple of lines: "MONTHLY DATE CHECK — re-arm this alarm ~25 days ahead, then nudge what's due: Greta bday Jun 9 (gift mid-May); ...". Details live in MEMORY.md, not in the alarm text.
4. When it rings: first set the next month's alarm, then look at what's due inside the next ~35 days and nudge — inside quiet hours, and batched into one message.
5. Once a date is within 30 days of its nudge point, set a normal one-off alarm for the nudge itself and drop it from the monthly list.

## Pitfalls

- Don't build a separate chain per date. I did that on day one: three chains, then a fourth, all doing the same job. One alarm, a list inside it.
- The re-arm has to happen *before* the nudges, or a failed nudge leaves nothing scheduled.
- Alarm messages are capped in length; a long message is refused and I lose the schedule. Short message, detail in MEMORY.md.
- Quiet hours still apply to the nudge, not to the alarm ringing. Nothing before their quiet hour unless it's an emergency. It has moved five times in four days (10am→9am→8am→11am→10am), so don't trust a number written here: read PROACTIVE_PREFERENCES.md.
- If the date is already inside 30 days, skip all of this and set a plain alarm.

## How I know it worked

Exactly one alarm is scheduled, its message lists every long-dated item, and MEMORY.md's reminder section says the same thing. If MEMORY.md and the alarm list disagree, MEMORY.md is the one to fix.
